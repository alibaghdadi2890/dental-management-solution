# Service & Diagnosis Catalogs Implementation Plan

> **For agentic workers:** executed inline in the authoring session (the user asked for spec → plan
> → implementation in PR-sized steps, as in feature 1). Steps use checkbox (`- [ ]`) syntax for
> tracking. Code lives in the commits, not in this file; each task names its files, the test cases
> written first, and the verification commands.

**Goal:** Feature 2 of the MVP per `docs/superpowers/specs/2026-09-27-catalogs-design.md`.

**Architecture:** `clinical` owns `procedures` and `diagnoses` (RLS, soft delete) behind
`CatalogService`; batch saves are validated as a whole in `clinical/domain`; prices are money in the
tenant currency read from `tenancy`; the default template is seeded on `TenantProvisioned` (events
only, ADR-0014) and by an idempotent endpoint. The SPA ports `Catalog.dc.html` on a pure draft
model and adds the Overview seed button.

**Tech Stack:** NestJS 11.2, Drizzle 0.45 (+ drizzle-kit), Postgres 17 RLS, Zod 4, nestjs-zod,
React 19, TanStack Router/Query, Radix primitives, Vitest 5, Testcontainers, Playwright.

**Gate for every step (a)–(c):** `pnpm lint && pnpm typecheck && pnpm test && pnpm build` green,
`pnpm format:check` clean, docs for the touched modules updated, one commit per task on
`feat/catalogs`.

### Task B3: `CatalogService`, routes, events, seeding

**Files:** `modules/clinical/application/{catalog.service,catalog-seeding.subscriber}.ts`,

`test/integration/tenant-isolation-services.int-spec.ts`, `tenant-isolation.int-spec.ts` (RLS list).

- [ ] Integration first:
  - provisioning seeds 12 services + 14 diagnoses in POC order with the tenant currency, audit rows
    with actor kind `system`; `POST /catalog/seed-default` then returns `{0,0}`;
  - after deleting every row, seed-default seeds again;
  - `PUT /catalog/services` creates + updates in one call, returns the full list; code swap between
    two rows succeeds; duplicate against a stored row → 422 `validation_failed` with
    `errors[0].path = 'items.1.code'` and nothing saved; unknown id → 404 `catalog.not_found`;
    blank name → 400 `validation_failed` `items.0.name`;
  - currency: tenant switched to EUR — editing a name keeps USD, changing the price stamps EUR;
  - `DELETE` soft-deletes (gone from list, code reusable); `isInUse` stubbed true (spy on the
    service) → 409 `catalog.in_use`, row kept; `POST …/deactivate` → `active: false`;
  - audit: `catalog.service.update` with before/after, and a `CatalogChanged` entry;
  - frontdesk: `GET` 200, `PUT`/`DELETE`/deactivate/seed → 403 `forbidden`;
  - diagnoses: same happy path + duplicate.
  - Isolation: A's owner sees only A's rows; B's ids → 404 on PUT/DELETE/deactivate and B unchanged.
- [ ] Implement (service methods per spec; subscriber catches and logs; module imports
      `TenancyModule`, `AuditModule`).
- [ ] Docs: `docs/modules/clinical.md` (status, owned tables, API, events, deps), ADR-0014, ADR-0015,
