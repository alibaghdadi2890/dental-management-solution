# Patients Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task by task. Steps use
> checkbox (`- [ ]`) syntax for tracking. As in features 1–2, code lives in the commits, not in
> this file. Each task names its files, the test cases to write first, and the verification
> commands.

**Goal:** Feature 3 of the MVP per `docs/superpowers/specs/2026-09-27-patients-design.md`
(decisions Q1–Q17).

**Architecture:**

- `patients` owns `patients` and `patient_counters` (RLS; archive = `deleted_at`) behind
  `PatientsService`. The service validates dentists through `users` and reads the time zone and
  country from `tenancy`.
- A new `billing` module owns `ledger_entries` and depends on `patients`. It orchestrates create
  with an opening balance, and it composes the patient views that need balances: _Owes balance_,
  sort by balance, and CSV export.
- Merges re-point ledger entries through a BullMQ tenant job.
- The SPA ports `Patients.dc.html`, the record shell from `ClinicalWorkspace.dc.html` and the ⌘K
  palette. Each is built on pure form, query and merge models.

**Tech Stack:** NestJS 11.2, Drizzle 0.45 (+ drizzle-kit), Postgres 17 RLS, BullMQ, Zod 4,
nestjs-zod, libphonenumber-js (new), React 19, TanStack Router/Query, Radix primitives, Vitest 5,
Testcontainers (Postgres + Redis), Playwright.

**Gate for every task:**

- `pnpm lint && pnpm typecheck && pnpm test && pnpm build` is green and `pnpm format:check` is
  clean.
- Docs for the touched modules are updated.
- One commit per task on `feat/patients`, ending with the `Co-Authored-By` trailer.
- Before the first integration run, pre-pull `postgres:17-alpine` and `redis:7-alpine`, because
  pulls are slow on this machine. If a DB or Redis connection fails, check which process owns the
  port before debugging code.

**Conventions to follow (read before starting):**

- Module pattern: `apps/api/src/modules/clinical/` (`catalog.service.ts`, `catalog.controller.ts`,
  `catalog-store.ts`, repositories, `domain/*-errors.ts`, `events/`, `index.ts`).
- DB helpers: `apps/api/src/platform/db/columns.ts` provides `idColumn`, `tenantIdColumn`,
  `tenantIsolationPolicy` and `timestamps`. `TenantDb.run()` joins an open transaction.
  `unique-violation.ts` maps index violations.
- Errors: `DomainError` subclasses in `domain/*-errors.ts` (see `clinical/domain/catalog-errors.ts`).
  `ValidationFailedError` gives 422s with `errors[].path`.
- Access: `@RequirePermission()` from `platform/http/route-access.ts` (one permission per route).
  Services re-check with `RequestContext.requirePermission()`.
- Events: `EventBus.create()` / `publish()` dispatch after commit; subscribe with
  `@OnDomainEvent()`. Audit: `AuditService.record()` inside the transaction.
- Jobs: `TenantJobs.enqueue(queue, name, payload, { jobId })`, and `TenantWorker` subclasses with
  `@Processor(name)`.
- Tests:
  - Unit specs sit next to the source (`*.spec.ts`). Integration specs live in
    `apps/api/test/integration/*.int-spec.ts`, with helpers in `apps/api/test/support/`
    (`tenants.ts`, `session.ts`, `http.ts`).
  - Web specs are `*.spec.ts(x)` next to the source. E2E specs are in `apps/web/e2e/`.
- Web primitives:
  - `components/ui/list.tsx`: `ViewTabs`, `SearchInput`, `TableCard`, `TableHead`,
    `SkeletonRows`, `EmptyState`, `ErrorState`, `Pill`.
  - `components/ui/right-panel.tsx`, `confirm-context.ts`, `toast-context.ts`, `menu.tsx`,
    `field.tsx`.
  - `components/unsaved-changes-guard.tsx`, `lib/format.ts`, `lib/api.ts` (`apiFetch`),
    `features/auth/use-permission.ts`.
- Migrations: `pnpm --filter @dcm/api db:generate --name <name>` produces them. Review the SQL
  (RLS policies, indexes, enums) before committing. Never edit a committed migration.

    - archive and restore with B's id give 404 and leave B unchanged;
    - A's search never returns B's rows;
    - A's creates leave B's counter unchanged.
