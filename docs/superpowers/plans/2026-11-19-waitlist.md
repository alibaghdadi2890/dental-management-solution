# Waitlist — implementation plan

Spec: `docs/superpowers/specs/2026-11-19-waitlist-design.md` (W1–W7, O1–O4, F1–F2, S1–S6).

Ground rules: nothing is committed until the owner asks; migration 0063 only adds; existing API
shapes only gain fields; no queue or job; per task the affected tests and that package's
typecheck, everything once at the end, then one review over the working tree.

1. **Contracts** — `waitlist.ts` (wishes, entry, opening, fit row, every route schema, pure
   helpers: `waitlistUntilDefault`, `describeWishes` facts); `scheduling.ts` gains `waitlist` /
   `fromWaitlist` on the appointment, `waitlist` on book and edit, `waitlist` on cancel,
   `onWaitlist` on the follow-up; `audit.ts` prefixes; `dashboards.ts` `openingsToFill`.
2. **Migration 0063** — `waitlist_entries`, `waitlist_left_open`, `appointments.waitlist_entry_id`;
   RLS, indexes, no deletes.
3. **Domain** — `domain/openings.ts`, `domain/waitlist-fit.ts`, `domain/waitlist-order.ts` with
   exhaustive specs (adjacent, grid, DST, closed days, hours edge, midnight, every B2 rule, B3).
4. **Persistence and services** — `WaitlistRepository`, `WaitlistService` (entries, rules),
   `OpeningsService` (openings, fits, fill, leave open); hooks in `AppointmentsService` (book,
   edit, cancel, restore, move, merge, archive, deactivate) and `FollowUpsService` (decline,
   `onWaitlist`); presenter fields; summary `openingsToFill`; audit `actorKind` override.
5. **HTTP** — the routes of the spec; errors in `scheduling-errors.ts`.
6. **API tests** — integration: fill as move and as booking (atomic, race, idempotent, follow-up
   taken), entry follows a move, cancel tick and restore, merge, archive, deactivate, decline;
   tenant isolation for the new tables and routes.
7. **SPA** — `features/scheduling/waitlist/` (api, provider, add/edit panel, wishes fields, fill
   panel, view, Today lane, words); toolbar, page, card mark, popover, cancel tick, panels' tick,
   slot finder, record card, worklist and checkout menus, toasts; dashboard line; activity
   sentences; the permission description; en/ar/fr.
8. **Docs** — ADR-0103 to ADR-0107, `docs/modules/scheduling.md`, `audit.md`, `dashboards.md`,
   CLAUDE.md §4, §8, §12.
9. **E2E** — `apps/web/e2e/waitlist.spec.ts`: book with the tick → cancel another → toast → Fill →
   moved → the chain.
10. **Finish** — format, lint, typecheck, all tests, e2e; one review; status memory.
